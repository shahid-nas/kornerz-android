## Why

> **See also:** [`docs/architecture.md`](../../../docs/architecture.md) for the MVVM + Repository + UDF contract, `AsyncValue<T>`, `Channel<NavEvent>`, module boundaries, Hilt scopes, and the canonical library list that every artifact in this change conforms to.

Phases P0–P4 ship a populated Home, Kornerz, and Nooks tab on top of a real Firebase backend — but the iOS app's "Connect" experience (join a community video room from a live Nook) is the product's defining feature, and the Android app has no path into it yet. The Nooks tab's live `LiveKornerCard` already renders a static "Join" button (placed there in P4 with a code comment that defers the navigation to this phase), and the `Nook` model already carries `sessionId: String?` populated by `NookFirestoreApi`, so the entry point and the Vonage session identifier are both in place — only the call itself is missing. This change (P9 — codename *Connect*) wires the static Join button to a new `feature/videocall` module that opens a Vonage video room over the same WebSocket token service the iOS app uses (`ws://ws.kornerz.com:80/`), reusing the iOS Vonage API key for the demo and rotating to a dedicated Android key before shipping. Because P5 (Loops), P6 (Profile/Notifications), P7 (Create Community/Admin), and P8 (Premium/IAP) are independent sibling phases in the dependency graph and have no call into the video call path, this change is shippable ahead of them and unblocks the end-to-end "two phones join a community room" demo.

## What Changes

- Add a new `feature/videocall` module with the standard `feature.*` scaffolding, hosting the top-level `videocall/{sessionId}` route and the `VideoCallScreen` destination. The module depends on `core/model`, `core/network`, and `core/ui` per `architecture.md` §2.5.
- Add `VideoCallViewModel` (`@HiltViewModel`) exposing `VideoCallState(callStatus: AsyncValue<CallSession>, isVideoOn: Boolean, isAudioOn: Boolean)` and a `Channel<VideoCallNavEvent>` (arch §2.4). Mirrors iOS `SwiftUI/VideoCall/VideoCallViewModel.swift`.
- Add `SessionTokenService` (`@Singleton`) implementing the WebSocket handshake against `ws://ws.kornerz.com:80/` — sends the Vonage `sessionId` as bytes after the socket reaches `.connected`, awaits the JSON `{"msg": "<token>"}` reply, then disconnects. Mirrors iOS `Backend/Services/OpenTokTokenService.swift` + `WebSocketService.swift` one-for-one (auto-reconnect, 30 s ping, 5 s reconnect delay are out of scope — see "Out of scope" below).
- Add `VonageSessionController` (`@Singleton`) wrapping the Vonage Android SDK 2.34.0: builds `Session.Builder` with `apiKey = "47628671"` (shared with iOS for the demo; will rotate to a dedicated Android key before shipping) and the per-call `sessionId`, publishes the local camera, and subscribes to remote streams. Exposes `Flow<SubscriberSnapshot>` for the UI.
- Add `VideoCallRepository` (`@Singleton`) in `feature/videocall/data/` that orchestrates the two-step connect flow (`SessionTokenService.fetchToken(sessionId) → VonageSessionController.connect(token, sessionId)`), plus a `disconnect()` that tears down the publisher, unsubscribes, and disconnects the session. Returns `Result<Unit>` for connect/disconnect and a `Flow<CallSession>` for the live state.
- Add `VideoCallScreen` + `VideoCallContent` (`@Composable` + stateless renderer) rendering a top toolbar (community name + small publisher tile), a content area that hosts the subscriber grid (linear list of `SubscriberContainer`s for this phase; complex grid math deferred), a bottom toolbar (end-call, camera-flip, mute, video, hand-raise — hand-raise is a no-op affordance this phase, see D4), and an overlay loading state with status text. Mirrors iOS `SwiftUI/VideoCall/VideoCallView.swift`.
- Add `PublisherContainer` (`@Composable`) — `AndroidView` wrapper around Vonage `Publisher.view` per arch §1 and `project-brief.md` decision 1 ("Compose-first, with `AndroidView` wrappers only where vendored SDKs force it"). Mirrors iOS `SwiftUI/VideoCall/PublisherContainer.swift`.
- Add `SubscriberContainer` (`@Composable`) — same `AndroidView` pattern around `Subscriber.view`. Mirrors iOS `SwiftUI/VideoCall/SubscriberContainer.swift`.
- Add `VideoCallLoadingState` (`@Composable`) rendering the centered `ProgressView` + status text ("Authenticating", "Connecting", "Waiting for others to join") and the failure error card with a "Back" button. Mirrors iOS `SwiftUI/VideoCall/VideoCallLoadingState.swift`.
- Wire `feature/nooks`'s `LiveKornerCard` Join button (currently static) to emit a new `NooksNavEvent.JoinVideoCall(sessionId: String)` that the tab's nested `NavHost` translates into `navController.navigate("videocall/$sessionId")`. The `sessionId` is read from `nook.sessionId` (already on the `Nook` model from P4).
- Add `videocall/{sessionId}` as a destination inside the Nooks tab's existing nested `NavHost` in `feature/shell` so the Join button routes to it without leaving the Nooks tab. The bottom navigation bar is hidden while in the video call (iOS pushes full-screen, no bottom bar). The Kornerz tab is **not** wired in this phase — entry is Nooks tab only.
- Add `core/model` data classes: `SessionToken` (the `{"msg": "..."}` payload), `CallSession` (state aggregate passed to the UI), `SubscriberSnapshot` (per-stream UI model). No `@Serializable` persistence in this phase.
- Add `Vonage` Android SDK 2.34.0 to `gradle/libs.versions.toml`; confirm `OkHttp` is on the classpath (it is, transitively via Firebase) and add the explicit `okhttp` library alias if not already present (arch §3).
- Request runtime permissions `CAMERA` and `RECORD_AUDIO` from `VideoCallScreen` using `rememberLauncherForActivityResult` before initiating the connect flow; deny path renders an inline error with a "Grant permissions" CTA. `BLUETOOTH_CONNECT` and `MODIFY_AUDIO_SETTINGS` are added to `AndroidManifest.xml` per Vonage docs but are not runtime-requested in this phase.
- Pin the demo Vonage `apiKey` in `core/network/videocall/VonageConfig.kt` with a `TODO(android-key-rotation)` comment so the rotation before shipping is grep-able.
- Defer (out of scope this phase): the iOS raise-hand signal mechanism (D4), the dynamic "9 spots left" count (D5), the foreground service for ongoing calls (D6, will revisit if it becomes trivial), the complex subscriber grid math (D7), premium gating (D3), and Kornerz-tab entry (single entry point this phase, Nooks tab only).

## Capabilities

### New Capabilities

- `feature-videocall`: The video call screen (12.1), loading state (12.2), Publisher container (12.3), Subscriber container (12.4), and the `VideoCallViewModel` / `VideoCallState` / `VideoCallEvent` / `VideoCallNavEvent` UDF contract. Hosts the `videocall/{sessionId}` top-level destination. Mirrors iOS `SwiftUI/VideoCall/*`.
- `video-call-session`: The WebSocket-based session token handshake (`SessionTokenService` against `ws://ws.kornerz.com:80/`) and the `VonageSessionController` wrapper around the Vonage Android SDK. Owns the `SessionToken`, `CallSession`, and `SubscriberSnapshot` data models in `core/model`. The `VideoCallRepository` orchestrates both.

### Modified Capabilities

- `android-app-shell`: The Nooks tab's nested `NavHost` SHALL host a new `videocall/{sessionId}` destination reachable from the live nook card's Join button. While the `videocall/{sessionId}` destination is in the back-stack, the bottom navigation bar SHALL be hidden (iOS parity — the call is a full-screen experience). All other shell-level tab order, selection, and theming rules are unchanged.
- `nooks-tab`: The Nooks tab's `LiveKornerCard` Join button SHALL emit a navigation event that routes to `videocall/{sessionId}` where `sessionId` is the `sessionId` of the parent `Nook` (i.e., the nook whose live card is being rendered). When the `Nook.sessionId` is null, the Join button SHALL be hidden (the nook exists but is not associated with a Vonage room). All other `nooks-tab` requirements are unchanged.

## Impact

- New module: `feature/videocall` (convention plugin set mirrors `feature/nooks`; `namespace = "com.kornerz.feature.videocall"`). Imported only by `app` per arch §2.5.
- New code in `core/model` (`SessionToken`, `CallSession`, `SubscriberSnapshot`), `core/network` (`VonageConfig`, `OkHttp` `WebSocket` client wrapper), `feature/videocall` (`VideoCallScreen`/`Content`, `VideoCallLoadingState`, `PublisherContainer`, `SubscriberContainer`, `VideoCallViewModel`, `VideoCallState`/`Event`/`NavEvent`, `VideoCallRepository`, `SessionTokenService`, `VonageSessionController`, plus `VideocallRoute.kt` with the `composable("videocall/{sessionId}")` factory).
- Touched modules: `feature/nooks` (`LiveKornerCard` Join button wires `onClick` to a new `NooksNavEvent.JoinVideoCall(sessionId)`; `NooksContent` propagates the event; `Nook` projection includes `sessionId`), `feature/shell` (Nooks tab's nested `NavHost` adds `videocall/{sessionId}`; bottom bar is hidden while the videocall route is on top), `app` (Hilt module wires `SessionTokenService` and `VonageSessionController` as `@Singleton`s), `gradle/libs.versions.toml` (adds `vonage-android-sdk = "2.34.0"` and an explicit `okhttp` library alias), `AndroidManifest.xml` (adds `CAMERA`, `RECORD_AUDIO`, `BLUETOOTH_CONNECT`, `MODIFY_AUDIO_SETTINGS` permissions and the `android.hardware.camera` feature requirement).
- Dependencies added: Vonage Android SDK 2.34.0 (Maven Central; same family as iOS `OTXCFramework 2.33.0`). OkHttp WebSocket is already a transitive dependency of Firebase; we add an explicit library alias so the version is pinned in `libs.versions.toml`. No other third-party libraries are introduced — arch §3 is otherwise satisfied.
- Backend: zero new backend work. The WebSocket token-issuing service at `ws://ws.kornerz.com:80/` is the same one iOS uses. The Vonage project API key (`47628671`) is shared with iOS for the demo and must be rotated to a dedicated Android key before shipping (tracked as a `TODO(android-key-rotation)` in `VonageConfig.kt`). The `getusercountsinasession` Cloud Function is **not** wired in this phase (D5 — static "9 spots left" copy remains).
- Permissions: `CAMERA` and `RECORD_AUDIO` are requested at runtime before connect; denial renders an inline error card. `BLUETOOTH_CONNECT` and `MODIFY_AUDIO_SETTINGS` are declared in the manifest but are not runtime-requested this phase (Android 12+ requires `BLUETOOTH_CONNECT` at runtime, but the Vonage SDK does not need it for the demo path on a phone with a built-in mic).
- Localization: English only per `project-brief.md` §11.7; new strings ("Authenticating", "Connecting", "Waiting for others to join", "Grant permissions", "End call", "Camera", "Microphone", "Video", "Hand raised") are added to `core/ui/.../strings.xml` as the only `values/` resource.
- Out of scope (deferred to follow-up or P10): iOS raise-hand signal, dynamic "9 spots left" count, foreground service for ongoing calls, complex subscriber grid math, premium gating, entry from the Kornerz tab, deep-link entry into the video call, screen recording, reconnection on transient network drops, recording and playback.
