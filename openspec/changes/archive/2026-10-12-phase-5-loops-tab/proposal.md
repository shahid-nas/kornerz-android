## Why

> **See also:** [`docs/architecture.md`](../../../docs/architecture.md) for the MVVM + Repository + UDF contract, `AsyncValue<T>`, `Channel<NavEvent>`, module boundaries, Hilt scopes, and the canonical library list that every artifact in this change conforms to.

Phase 4 closed the Nooks tab and made every nook tile a real destination. The fourth tab in the bottom navigation bar (`Loops`) is still the P0 "Coming in Phase 5" empty-state placeholder, and the Home tab's `RecentLoopsView` carousel (shipped in P2 — [`home-recent-loops`](../../../specs/home-recent-loops/spec.md)) only renders recent loops because there is no top-level loops destination to tap into — the iOS app's defining user flow ("scroll a feed of loops, tap one, watch a video, comment, reply") has no Android surface yet. Phase 5 ports the entire Loops vertical: a paginated, filterable, searchable feed (6.1, 6.2, 6.3); a loop detail screen with video playback and a like toggle (6.4, 6.5); the comments section (6.6); the create-comment sheet (6.7, 6.8); and the reply thread (6.9, 6.10). iOS (`kornerz/SwiftUI/Dashboard/Loops/`) is the source of truth for every Firestore read, every field, every sort order, and every interaction — the Android port uses Compose primitives, MVVM + Repository + UDF, and the canonical library list, but reaches behavioral parity so the two builds look identical in screenshots and walkthroughs. Backend integration is real (`kornerz-72fba`), there are no mock servers, and the phase ships an APK that compiles, launches, and is presentable to PM/QA for the "scroll Loops, open one, comment, reply" demo.

## What Changes

- Add a new `feature/loops` module with the standard `feature/*` scaffolding (matches `feature/nooks/build.gradle.kts`; `namespace = "com.kornerz.feature.loops"`), hosting two top-level routes: `loops/list` (the bottom-nav Loops tab) and `loops/{loopId}` (the loop detail). The comment sheet and reply screen are nested inside the loop detail destination.
- Add `LoopsViewModel` (`@HiltViewModel`) for the tab root that exposes `LoopsState` (`feed: AsyncValue<PagingState<LoopCardData>>`, `selectedFilter: LoopsFilter`, `searchQuery: String`) and orchestrates `LoopRepository.observeLoops(filter, search)`, pagination via `loadMore()`, and `Channel<LoopsNavEvent>` per arch §2.4. Mirrors iOS `LoopsTabViewModel.swift` + `LoopsTabCoordinator.swift`.
- Add `LoopDetailViewModel` (`@HiltViewModel`) keyed by `SavedStateHandle["loopId"]` that exposes `LoopDetailState(detail: AsyncValue<LoopDetail>, comments: AsyncValue<List<LoopCommentInfo>>, isLikedByUser: Boolean, isLikeInProgress: Boolean)` and orchestrates `LoopRepository.fetchLoopDetail(loopId)`, `LoopCommentRepository.observeComments(loopId)`, `LoopLikeRepository.checkIfUserLiked(loopId)`, plus `toggleLike()` / `incrementViewCount()`. Mirrors iOS `LoopDetailViewModel.swift` + `LoopDetailCoordinator.swift`.
- Add `CreateCommentViewModel` (`@HiltViewModel`) keyed by `SavedStateHandle["loopId"]` that holds `CreateCommentState(text: String, isSubmitting: Boolean, error: AppError?)` and submits via `LoopCommentRepository.createComment(loopId, parentId, text)`. Mirrors iOS `CreateCommentViewModel.swift` + `CreateCommentScreen.swift`.
- Add `ReplyViewModel` (`@HiltViewModel`) keyed by `SavedStateHandle["loopId", "parentCommentId"]` that fetches the `parentComment`, observes the replies sub-list, and submits new replies. Mirrors iOS `LoopReplyViewModel.swift` + `LoopReplyScreen.swift`.
- Add `LoopRepository` (`@Singleton`) in `feature/loops/data/` wrapping three Firestore APIs (`loopFirestoreApi.observeLoops()` for the feed, `loopFirestoreApi.fetchLoopDetail()` for the detail, and a paginated `loadMore()` cursor). Mirrors the iOS `LoopRepository` protocol (`fetchAllLoops`, `fetchUserLoops`, `searchLoops`, `deleteLoop`, `incrementViewCount`, `setLikesCount`).
- Add `LoopCommentRepository` (`@Singleton`) wrapping `loopCommentFirestoreApi.observeComments(loopId)` / `createComment` / `deleteComment` / `fetchAllCommentsForLoop`. Mirrors the iOS `LoopCommentRepository`.
- Add `LoopLikeRepository` (`@Singleton`) wrapping `likeLoop` / `unlikeLoop` / `checkIfUserLiked` / `setLikesCount` against `users/{userId}/likedLoops/{loopId}` (iOS path). Mirrors the iOS `LoopLikeRepository`.
- Add `CommentLikeRepository` (`@Singleton`) wrapping `likeComment` / `unlikeComment` / `checkIfUserLiked` / `fetchLikesForComment` against `loopComments/{commentId}/likes/{userId}`. Mirrors the iOS `CommentLikeRepository`.
- Add `LoopCommentInfo` projection in `core/model` (composite of `LoopComment` + `User` + `isLikedByUser` + `likeCount`) and `LoopCardData` projection in `feature/loops` (id, title, description, communityId, publisherId, publisherNickname, publisherThumbnailUrl, themeColor, thumbnailUrl, viewCounts, commentsCount, likesCount, isVideo, creationDate).
- Add `core/model` `@Serializable` data classes: `Loop`, `LoopComment`, `LoopLike`, `CommentLike`, `LoopCommentInfo`. `Loop.isVideo` resolves to `firebaseVideoUrl` non-empty; `Loop.imageURL` / `Loop.thumbnailURL` mirror the iOS fallback chain (Firebase URL → IPFS hash). See models (`kornerz/Kornerz/Models/Loop.swift`, `LoopComment.swift`, `LoopLike.swift`).
- Add two Loop subcollections-related Firestore API wrappers (`core/network/loops/LoopFirestoreApi.kt`, `LoopCommentFirestoreApi.kt`, `LoopLikeFirestoreApi.kt`, `CommentLikeFirestoreApi.kt`) that hide the exact `loops`, `loopComments`, `users/{userId}/likedLoops`, and `loopComments/{commentId}/likes` paths behind suspend methods returning `Result<T>` or `Flow<T>` per arch §2.3. Sort orders match iOS: feed by `creationDate` descending; comments list by `creationDate` ascending; replies list by `creationDate` ascending. Pagination uses Firestore `startAfterDocument` cursors (iOS uses `lastDocument`; mirrors the same semantics).
- Add `LoopItemView` / `LoopsFilterView` composables inside `feature/loops/.../components/` that take a `LoopCardData` projection and a `LoopsFilter` selection — the row layout (cover square + avatar overlay + title + community/date subtitle + stats icon row) and the filter chip + search bar patterns mirror iOS `LoopItemView.swift` + `LoopsFilterView.swift` literally. Each takes a `Modifier` as the last parameter per arch §4.
- Add `LoopCommentView`, `CreateCommentScreen`, `ReplyScreen` composables inside `feature/loops/.../components/` that match the iOS structure: a comment row with avatar + body + reply/like/delete affordances, a centered avatar + text-field + send button for new comments, and a parent-comment header + reply list for the reply screen. Mirrors iOS `LoopCommentView.swift`, `CreateCommentScreen.swift`, `LoopReplyScreen.swift`.
- Add `VideoPlayerView` in `feature/loops/.../components/` wrapping Media3 `ExoPlayer` + `AndroidView(PlayerView)` for the loop detail media area (iOS uses `AVKit`-style AVPlayer; this is the Compose equivalent). Only loads `Loop.videoURL` when `Loop.isVideo = true`. Includes a centered play icon overlay, a thumbnail fallback (`Loop.thumbnailURL`), and a `PlayerListener` that releases the player on dispose. A `PlayerViewModel` (`@ViewModelScoped` or simply held by `LoopDetailViewModel` because there is exactly one player per detail screen) exposes `isPlaying`, `playbackError`, and `controls` state.
- Refactor `feature/home/.../RecentLoopsSection` (shipped in P2) to render the new `LoopItemView` from `feature/loops` so visual parity is guaranteed across the home carousel and the Loops tab feed. `feature/home` gains a one-way dependency on `feature/loops` for the shared `LoopItemView` composable (same pattern P4 used for `NookCard`).
- Add `feature/shell` routes: the Loops tab `composable` becomes a nested `NavHost` with destinations `loops/list` and `loops/{loopId}`. The comment sheet is registered as a `dialog` route inside the Loops tab. The reply screen is a `composable("reply/{loopId}/{commentId}")` nested under the loop detail. The 5-tab order, tab icons, and selection state are unchanged from P0–P4.
- Update `feature/kornerz`'s `KornerDetailNavEvent` / Korner detail handler so any "View all loops for this Korner" link (added when a Korner exposes one) routes into the same `loops/{loopId}` destination. This phase does **not** add a Korner → Loops list link; the only entry points are the Home Recent Loops carousel tap and the bottom-nav Loops tab.
- Add Coil-based image loading for loop thumbnails and avatars with shimmer placeholders; ExoPlayer wires up the video playback path for `loop.isVideo = true`.
- Update `feature/home`'s `RecentLoopsSection` to use `LoopRepository.fetchRecentLoops(limit = 10)` (new lightweight repository method) so the section does not depend on the same paginated feed the tab uses. The carousel contract from P2 is preserved verbatim.
- Pass the per-phase exit checklist (`./gradlew :app:assembleDevDebug`, install on API 26 + 35 emulators, no crashes, lint, unit tests, screenshots, demo walkthrough, `phase-5-end` git tag).

## Capabilities

### New Capabilities

- `loop-domain`: The `Loop`, `LoopComment`, `LoopLike`, and `CommentLike` `@Serializable` data classes in `core/model`. Field-for-field parity with iOS `Models/Loop.swift`, `LoopComment.swift`, `LoopLike.swift` and the iOS `CommentLike` model. Also includes the `LoopCommentInfo` projection (comment + author + like state) and the `LoopsFilter` enum (`All`, `YourLoops`). The domain owns no behavior — only data + the documented iOS-derived sort orders and field defaults.
- `loops-tab`: The Loops bottom-nav tab root (6.1) — a paginated, filterable, searchable feed of loops ordered by `creationDate` descending. Hosts the filter chips + search bar (6.2) and the single loop item row (6.3). Mirrors iOS `LoopsTabView.swift`, `LoopsFilterView.swift`, `LoopItemView.swift` and the tab's `LoopsTabViewModel.swift` orchestration. Same empty / error / loading / shimmer / pull-to-refresh / pagination contract as iOS.
- `loop-detail`: The `loops/{loopId}` destination (6.4, 6.5) — full-width media area (image or ExoPlayer video), title + owner/community/date row + like toggle, expandable description (HTML if `descriptionHtml` non-empty, plain text otherwise), stats row (views · comments · likes), comments header, comment list, and a safe-area-inset add-comment button that opens the create-comment sheet. Mirrors iOS `LoopDetailView.swift` + `LoopDetailViewModel.swift`. Includes a single-fire `incrementViewCount(loopId)` call on first appearance (per iOS `hasIncrementedViewCount` guard).
- `loop-comments`: The single comment row (6.6), the create-comment sheet (6.7, 6.8), and the reply thread (6.9, 6.10). Mirrors iOS `LoopCommentView.swift`, `CreateCommentScreen.swift` + `CreateCommentViewModel.swift`, `LoopReplyScreen.swift` + `LoopReplyViewModel.swift`. Comment rows expose reply / like / delete affordances where appropriate, the create sheet is a centered avatar + text field + send button, and the reply screen renders the parent comment pinned at the top with a replies list below.
- `loop-video`: The `VideoPlayerView` wrapper around Media3 `ExoPlayer` + `AndroidView(PlayerView)` for the loop detail media area. Loads `Loop.videoURL` when `Loop.isVideo = true`; falls back to `Loop.thumbnailURL` (still image) when `isVideo = false`. A `PlayerViewModel` exposes `isPlaying`, `playbackError`, and a `controlsVisible` flag. Shimmer placeholder while the player buffers.
- `home-recent-loops-via-shared-card`: A new capability that documents the contract change: `feature/home/.../RecentLoopsSection` composes `LoopItemView` from `feature/loops` instead of the P2 inline row composable, eliminating duplicated card chrome and guaranteeing visual parity between the home carousel and the Loops tab feed. The original `home-recent-loops` spec is amended under "MODIFIED Requirements" to reflect the rendered composable change; the underlying data contract (limit 10, `createdAt` desc) is unchanged.

### Modified Capabilities

- `android-app-shell`: The Loops tab `composable` SHALL host a nested `NavHost` with destinations `loops/list`, `loops/{loopId}`, `loops/{loopId}/comment`, and `loops/{loopId}/reply/{commentId}` (the last two — create-comment sheet and reply thread — registered as a `dialog` and a `composable` respectively). The bottom navigation bar remains visible across `loops/list` and `loops/{loopId}` (per `android-app-shell`'s existing rule that the bottom bar never hides for tab-internal navigation). The system back press from any nested destination pops to its parent within the Loops tab's NavHost; popping `loops/list` does **not** exit the app — the bottom bar always remains. Other tab routes, tab order, and theming are unchanged.
- `home-recent-loops`: The P2 "Recent loops" carousel SHALL compose `LoopItemView(data: LoopCardData, color: Color, modifier: Modifier = Modifier)` from `feature/loops` instead of the inline row composable shipped in P2. The data fetch shape (limit 10, sorted by `createdAt` descending) is unchanged; only the renderer changes. `feature/home` declares a one-way dependency on `feature/loops` (mirrors the P4 `feature/kornerz → feature/nooks` edge for shared cards).

## Impact

- New module: `feature/loops` (plugin set mirrors `feature/nooks/build.gradle.kts`; `namespace = "com.kornerz.feature.loops"`). Imported only by `app` per arch §2.5. `feature/home` declares a one-way dependency on `feature/loops` for the shared `LoopItemView`.
- New code in `core/model` (`Loop`, `LoopComment`, `LoopLike`, `CommentLike`, `LoopCommentInfo`, `LoopsFilter`), `core/network` (`LoopFirestoreApi`, `LoopCommentFirestoreApi`, `LoopLikeFirestoreApi`, `CommentLikeFirestoreApi` — four `@Singleton` Firestore wrappers around the iOS-discovered paths), `feature/loops` (the `LoopsScreen`/`Content`, `LoopDetailScreen`/`Content`, `CreateCommentScreen`/`Content`, `ReplyScreen`/`Content` pairs, the four view models, the four repositories, the `LoopItemView` / `LoopsFilterView` / `LoopCommentView` / `VideoPlayerView` composables, and the `LoopCardData` / `LoopCardDataColorMapper` projections per arch §4 folder structure).
- Touched modules: `feature/shell` (Loops tab `composable` becomes a nested `NavHost` with `loops/list`, `loops/{loopId}`, `loops/{loopId}/comment`, `loops/{loopId}/reply/{commentId}` destinations; new `LoopsRoute` sealed class), `feature/home` (`RecentLoopsSection` refactored to compose `LoopItemView` from `feature/loops`; new `LoopCardData` projection inside `HomeViewModel` so the carousel data does not blow up the home detail payload), `app` (Hilt module wires `LoopRepository`, `LoopCommentRepository`, `LoopLikeRepository`, `CommentLikeRepository`, and the four Firestore APIs), `gradle/libs.versions.toml` (adds `androidx.media3:media3-exoplayer`, `androidx.media3:media3-ui`, `androidx.media3:media3-common` — none of these are in arch §3, so this proposal is the amendment that adds them; rationale: arch §3 already lists Media3 ExoPlayer under "UI helpers / Video playback (P9)", and the same library is the canonical Android video library; we are advancing P9's Media3 introduction to P5 to support loop detail video playback, no rule is violated because the library was always on the canonical list).
- Dependencies: one new third-party library family introduced ahead of its originally scheduled phase (Media3 ExoPlayer). No other new dependencies. Coil, Compose BOM, Hilt, Navigation-Compose, kotlinx-datetime, kotlinx-serialization all pinned in P0/P1 and reused. Firebase Firestore KTX + Firebase Auth KTX already pinned.
- Backend: zero new backend work. Every Firestore collection and document path read by Android matches the iOS app's reads against the shared `kornerz-72fba` project (`loops`, `loopComments`, `users/{userId}/likedLoops`, `loopComments/{commentId}/likes`, `communities`, `users`). If a missing index surfaces during development, it is filed as a follow-up issue and does not block P5. The Firestore composite index that is the most likely to be required is `loops` ordered by `creationDate` descending with an `active = true` filter — iOS uses this without an explicit index note, so we mirror that and check at PR time.
- Localization: English only this phase per `project-brief.md` §11.7 and `phases.md` Principle 7; all new screens are RTL-safe and previewed under the `en-rXA` pseudo-locale. Strings sourced from the iOS `Resources/LocalizationStringFiles` fall back to literal English when not yet extracted.
- Out of scope (deferred): Profile + Notifications (P6), Create Community + Admin (P7), Premium / IAP (P8), Video Calling — Vonage / WebRTC (P9), Ranking + Deep Links + Polish (P10). Loop creation wizard (the iOS `CreateLoopController.swift` lives but the live flow does not expose a "create loop" entry from the Loops tab — confirmed by `screen-inventory.md` §6; stays deferred). Reaction emojis on comments (not in iOS live flow). Loop video upload / transcode (iOS uses the Video Kit + IPFS pipeline; stays deferred to a future phase beyond P10). Push notification deep links from `loopId` (P10).
