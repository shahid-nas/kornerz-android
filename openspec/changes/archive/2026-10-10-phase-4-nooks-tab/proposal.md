## Why

> **See also:** [`docs/architecture.md`](../../../docs/architecture.md) for the MVVM + Repository + UDF contract, `AsyncValue<T>`, `Channel<NavEvent>`, module boundaries, Hilt scopes, and the canonical library list that every artifact in this change conforms to.

Phase 3 produced a working Kornerz tab where a signed-in Android user can browse communities and view a Korner's cover, about, current nook, upcoming nooks list, and members. The Korner detail screen already renders two nook sections (`CurrentNookSection` and `NooksListSection`) — but tapping any nook tile surfaces a `Coming in Phase 4` snackbar because no standalone nook destination exists, and the third tab in the bottom bar (`Nooks`) is still the P0 "Coming in Phase 4" empty-state placeholder. Phase 4 closes that gap by implementing the entire Nooks top-level tab (5.1, 5.2, 5.3) so the user has a dedicated discovery surface for live and scheduled nooks across every Korner, and so the Korner detail's nook tiles resolve to a real destination instead of a snackbar. Every screen is a 1:1 port of the iOS `SwiftUI/Dashboard/Nooks/*` views so the Android and iOS builds look identical in screenshots and walkthroughs.

## What Changes

- Add a new `feature/nooks` module with the standard scaffolding (`kornerz.android.feature.compose.hilt`), hosting the Nooks tab top-level route (`nooks/list`) that renders the cross-Korner nooks feed.
- Add a `NooksViewModel` (`@HiltViewModel`) for the tab root that exposes `NooksState` (an `AsyncValue<NooksFeed>` partitioning nooks into `live: List<Nook>` and `scheduled: List<Nook>`), fetches via `NooksRepository`, and routes into nook detail through `Channel<NooksNavEvent>` per arch §2.4. Mirrors iOS `NooksTabView.swift` + `NooksTabViewModel.swift`.
- Add `NookCard` (`@Composable`) and `ScheduledNookCard` (`@Composable`) — the two row variants rendered inside the Nooks tab list and reused wherever a nook needs a card body. Mirrors iOS `NookView.swift` and `ScheduledNookView.swift`. The tiles currently rendered inside `korner-detail`'s `NooksListSection` and `CurrentNookSection` are refactored to compose these shared cards so visual parity is preserved across both surfaces.
- Add `NooksRepository` (`@Singleton`) backed by Firestore reads that mirror the iOS `NooksTabViewModel.fetchData()` calls — a single pass that fetches every `Korner` the user can see (same unfiltered discovery query as `kornerz-tab`), then merges the `communities/{id}/events` subcollections and partitions the result into live (`isLive = true`, ordered by `startDate` desc) and scheduled (`isLive = false`, ordered by `startDate` asc) lists. One repository call instead of N path-prefix scans.
- Add a `NookDetailViewModel` (`@HiltViewModel`) for the nook detail screen that holds `AsyncValue<NookDetail>` (the nook plus its parent `Korner`), shares a per-`nookId` instance via Hilt's `SavedStateHandle` factory. Mirrors iOS `NookDetailView.swift` + `NookDetailViewModel.swift` which the iOS app already routes to from the nook tiles built in P3.
- Add `NookDetail` `@Serializable` data class in `core/model` aggregating `nook: Nook` + `korner: Korner`. Spec in `nook-domain/spec.md`.
- Add Coil-based image loading for the nook cover and parent Korner cover with shimmer placeholders consistent with the `korner-detail` shimmer pattern from P3.
- Update `feature/shell` so the Nooks tab's `composable` no longer renders the P0 "Coming in Phase 4" placeholder; instead it hosts `NooksScreen`. The 5-tab order, tab icons, and selection state are unchanged.
- Add `NookDetailScreen` + `NookDetailContent` in `feature/nooks/` as a top-level destination reachable from any nook tile (Nooks tab, `korner-detail` Current Nook, `korner-detail` Nooks list). The system back button pops to the originating tab (the iOS coordinator already restores tab selection).
- Replace the `Coming in Phase 4` snackbar wired through `KornerDetailNavEvent.NavigateToNookDetail` in `feature/kornerz/` (shipped in P3) with a real navigation call into the new `nooks/{nookId}` destination.
- Refactor the `NookTile` and `CurrentNookView` composables inside `feature/kornerz/` so they delegate rendering to `NookCard` / `ScheduledNookCard` from `feature/nooks` — eliminates duplicated card chrome and guarantees iOS parity (the iOS source uses one card layout for all surfaces).

## Capabilities

### New Capabilities

- `nooks-tab`: Nooks tab root (5.1) — the top-level discovery feed reachable from the bottom navigation bar. Renders two sections: a "Live now" pinned section listing every nook with `isLive = true` as `NookCard` rows, and an "Upcoming" section listing every nook with `isLive = false` as `ScheduledNookCard` rows ordered by `startDate` ascending. Matches iOS `NooksTabView.swift`.
- `nook-card`: Single nook card (5.2) + scheduled/upcoming nook card (5.3) — the shared card composables used inside the Nooks tab list and reused by `feature/kornerz` for the Current Nook and Nooks list sections. Mirrors iOS `NookView.swift` and `ScheduledNookView.swift`.
- `nook-detail`: Nook detail destination reached when a user taps any nook tile (Nooks tab, Korner detail Current Nook, Korner detail Nooks list). Hosts a screen that renders the nook cover, title, scheduled date, and a back-to-Korner row showing the parent Korner. Shares `NookDetailViewModel` per `nookId` nav-arg via `SavedStateHandle["nookId"]`. Mirrors iOS `NookDetailView.swift`.
- `nook-domain`: the `NookDetail` data model in `core/model`. `Nook` and `Korner` already ship from `korner-domain` (P3) and are reused without modification; this capability adds the composite `NookDetail(nook, korner)` aggregate.

### Modified Capabilities

- `android-app-shell`: the Nooks tab route must render `NooksScreen` instead of the P0 "Coming in Phase 4" placeholder. The shell-level tab order, selection, insets, and theming requirements are unchanged. The Nooks tab now owns a nested `NavHost` for the cross-Korner nook list only (`nooks/list`) — the nook detail destination is hosted as a per-tab nested graph inside both the Nooks tab and the Kornerz tab so back-stack rules match the iOS coordinator (deep-link from Nooks tab pops to Nooks tab; deep-link from Korner detail pops to Korner detail).
- `korner-detail`: the `KornerDetailNavEvent.NavigateToNookDetail(nookId)` handler must resolve to the new `nooks/{nookId}` destination instead of the P3 "Coming in Phase 4" snackbar. The `NookTile` composable inside `NooksListSection` and the tile inside `CurrentNookSection` are refactored to compose `NookCard` / `ScheduledNookCard` from `feature/nooks` so visual parity is preserved across both surfaces. The `korner-detail` and `korner-domain` capability contracts are unchanged from P3.

## Impact

- New module: `feature/nooks` (convention plugin `kornerz.android.feature.compose.hilt`, `namespace = "com.kornerz.feature.nooks"`). Imported only by `app` per arch §2.5.
- New code in `core/model` (`NookDetail`), `core/network` (`NookFirestoreApi` wrapper around the same Firestore paths iOS reads — `communities` + `communities/{id}/events`), `feature/nooks` (`NooksScreen`/`Content`, `NooksState`/`Event`/`NavEvent`, `NooksViewModel`, `NooksRepository`, `NookCard`, `ScheduledNookCard`, `NookDetailScreen`/`Content`, `NookDetailState`/`Event`/`NavEvent`, `NookDetailViewModel`, plus composables for the nook cover header, nook metadata block, and back-to-Korner row per arch §4).
- Touched modules: `feature/shell` (Nooks tab `composable` now hosts `NooksScreen` with nested `NavHost`; new `nooks/{nookId}` destination hosted as a per-tab nested route reachable from both the Nooks tab and the Korner detail), `feature/kornerz` (`NookTile` + `CurrentNookView` composables refactored to delegate to `NookCard` / `ScheduledNookCard`; `KornerDetailNavEvent.NavigateToNookDetail` handler no longer surfaces a snackbar but pushes the new `nooks/{nookId}` destination), `app` (Hilt module wires `NooksRepository` and `NookFirestoreApi`), `gradle/libs.versions.toml` (no new dependencies — Coil, Coroutines, Compose BOM, Hilt, Navigation-Compose, kotlinx-datetime already pinned in P0).
- Dependencies: none outside arch §3. The iOS Nooks tab does not animate the nook cover, so Lottie is not added for P4. ExoPlayer is **not** introduced for P4 — the nook detail screen mirrors iOS, which renders a still cover image; Loops tab video playback ships in P5.
- Backend: zero new backend work. Every Firestore collection and document path read by Android matches the iOS app's reads against the shared `kornerz-72fba` project (`communities`, `communities/{id}/events`, `users`). If a missing index surfaces during development, it is filed as a follow-up issue and does not block P4.
- Localization: English only this phase per `project-brief.md` §11.7 and `phases.md` Principle 7; all new screens are RTL-safe and previewed under the `en-rXA` pseudo-locale.
- Out of scope (deferred): Loops tab (P5), Profile + Notifications (P6), Create Community + Admin (P7), Premium / IAP (P8), Video Calling (P9), Ranking + Deep Links + Polish (P10). Nooks tab search/filter (iOS shows a header placeholder — kept as a static element this phase). Member profile destination (P6). Join / leave Korner actions (not in iOS live flow). Nook start/end live state live-streaming via Firestore snapshot listeners (iOS uses a one-shot fetch — mirrored this phase; can move to a `Flow` snapshot listener in a follow-up). Recording or joining a nook video room (P9).
