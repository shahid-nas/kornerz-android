## Why

> **See also:** [`docs/architecture.md`](../../../docs/architecture.md) for the MVVM + Repository + UDF contract, `AsyncValue<T>`, `Channel<NavEvent>`, module boundaries, Hilt scopes, and the canonical library list that every artifact in this change conforms to.

Phases P0–P7 shipped a populated Home, Kornerz, Nooks, Loops, Profile, Notifications, and Admin-communities surface on the shared Firebase backend (`kornerz-72fba`). The `User` model already carries all four premium fields — `isUserPremium`, `subscriptionExpiryDate`, `subscriptionType`, `subscriptionPlatform` (`core/model/.../User.kt:38-41`) — but they are **dead on Android**: nothing writes them, `UserFirestoreApi.toUserOrNull()` never maps them back on read, `com.android.billingclient` is absent from the entire repository, there is no subscription screen, and there is no paywall gate. A Kornerz Android build can be installed and clicked through end-to-end and a user can still never subscribe, never be shown a trial, and never see a premium feature unlock. That is the single largest functional-parity gap left before the P10 parity demo.

Phase 8 ports the **Premium / IAP** vertical from iOS. iOS (`kornerz/Kornerz/InAppPurchase/SubscriptionController.swift`, `SubscriptionScreen.swift`, `SubscriptionSuccessScreen.swift`, `InAppManager.swift`, `kornerz/Kornerz/Models/User.swift:29-32` + `:86-91`, `kornerz/Kornerz/Backend/Repositories/UserRepository.swift:165-178`) is the **source of truth** for the three-screen structure, the two-plan catalog, the exact Firestore field set and platform tagging, and the paywall-gate conditions. The Android port substitutes Google Play Billing for StoreKit and substitutes an expiry-derived entitlement check for `InAppManager.currentEntitlements`, reaching behavioral parity so the two builds look identical in screenshots and walkthroughs. Backend integration is real (`kornerz-72fba`), no mock servers, and the phase ships an APK that compiles, launches, and is presentable to PM / Finance / QA for the "subscribe on Android, see premium unlock, cancel, see it expire" demo.

### iOS audit findings that scope this proposal

The iOS source was audited before scoping. Five findings materially changed the plan:

1. **There is no subscribe entry point in the iOS Profile menu.** `UserProfileVC.setupMenuList()` (`kornerz/Kornerz/HomeVC/ProfileVC/UserProfileVC.swift:75-110`) inserts `userDetail / notifications / completeRegistration / myData / reviewTutorial / privacyPolicy / logout / deleteAccount`. `TypeOfUserInfoCell` has no `.subscribe` / `.premium` / `.paywall` case. The paywall is reachable **only** through two automatic gates (post-login and tab-controller entitlement re-emit). Phase 8 therefore adds an Android-only "Premium" Profile row as the manual entry point, on top of the two parity gates. This is an Android-only surface with no iOS parity target — the same situation Phase 7 hit with the create-community wizard, and documented as such.
2. **`Constants.trialPeriodInSeconds` (`kornerz/Kornerz/Helper/Config.swift:117`, `7 * 24 * 60 * 60`) has zero readers.** The "1 week free" wording comes from App Store Connect's introductory offer (`SubscriptionViewModel.swift:73-79`), and the actual gate is purely `expiryDate > Date()` (`AppHelper.swift:39-45`). Android mirrors the semantics: the trial is Play's free-trial offer on the subscription base plan, and premium is derived from `subscriptionExpiryDate > now`. The 7-day constant is carried into `core/model` for documentation parity but is **not** the gate.
3. **`UserRepository.setUserPremium(expiryDate:type:)` (`:165-178`) writes only three fields** — `subscriptionExpiryDate`, `subscriptionPlatform: "iOS"`, `subscriptionType` — and **never writes `isUserPremium`**. The `isUserPremium` bit is derived locally from the expiry. Android mirrors the write exactly (`subscriptionPlatform = "Android"`) and derives the boolean, rather than writing a fourth field that iOS leaves alone.
4. **There are no Cloud Functions in this repository** (`glob **/*.ts` → no files; no `functions/` directory; no `firebase.json`). The RTDN webhook and Google Play Developer API verification named in `docs/phases.md:260-261` are deployed alongside the iOS infrastructure, not versioned here. Phase 8 follows the **P6 precedent** (`feature/profile/.../data/network/CloudFunctionsApi.kt`, which calls the `deleteUserAccount` callable that likewise is not in-repo): ship the Android-side callable client + the verification contract, and document the function as external. No function source is authored in this change.
5. **iOS has no deep-link or push path into the paywall.** `DeeplinkManager.DeepLink` (`kornerz/Kornerz/DeepLinks/DeeplinkManager.swift:13-54`) has no subscription case. Phase 8 does not add one. P10 owns deep links.

Two further iOS artifacts are deliberately **not** ported: `subscription_bg` (`SubscriptionScreen.swift:29`) is a missing image asset in the iOS bundle that renders blank at runtime, so Android ships a vector/solid equivalent rather than a broken bitmap; and `subscription_features.json` is loaded into `SubscriptionViewModel.featureFile` (`SubscriptionViewModel.swift:40-50`) but never bound to any view, so it is dead and the Android plans screen carries no "what's included" list. The legacy `InAppViewController` / `InappSuccesViewController` / `SubscriptionCell` pair is already excluded as dead code per `docs/screen-inventory.md:205`.

## What Changes

- Add a new `feature/subscription` Gradle module (`namespace = "com.kornerz.feature.subscription"`, mirroring `feature/profile/build.gradle.kts`) hosting the full P8 vertical, wired into `settings.gradle.kts` and `app/build.gradle.kts`.

- Add `com.android.billingclient:billing-ktx` (v7.x, satisfying the `docs/phases.md:259` "v6+" floor) to `gradle/libs.versions.toml` as the catalog alias `android-billing`. **This is the first third-party Play dependency in the codebase** — the library is entirely absent today (0 hits repo-wide). `settings.gradle.kts` uses `RepositoriesMode.FAIL_ON_PROJECT_REPOS`, so the catalog alias is the only correct insertion point; no per-module `repositories {}` block is added. The Play Billing library contributes `com.android.vending.BILLING` to the merged manifest, so no explicit `<uses-permission>` is added to `app/src/main/AndroidManifest.xml`.

- Add `BillingClientApi` (`@Singleton`) in `feature/subscription/data/billing/` — the single wrapper over `BillingClient`, following the `*FirestoreApi` wrapper convention used by `feature/community/data/network/` and `feature/profile/data/network/`. Exposes `connectionState: StateFlow<ConnectionState>`, `queryProductDetails(ids): Result<List<SubscriptionProduct>>`, `queryPurchases(): Result<List<PurchaseRecord>>`, `launchPurchase(productId): BillingPurchaseResult`, `acknowledge(token): Result<Unit>`, `restore(): Result<List<PurchaseRecord>>`, `endConnection()`. Follows the repo's `suspend fun … = runCatching { … await() }` shape via `kotlinx.coroutines.tasks.await` (the same bridge every existing `*FirestoreApi` uses); **no `withContext(Dispatchers.IO)`** is added, matching `core/network` (that qualifier exists only in `core/storage`).

- Add `SubscriptionRepository` (`@Singleton`) in `feature/subscription/data/` — the UDF-facing surface. Mirrors iOS `InAppManager` (`kornerz/Kornerz/InAppPurchase/InAppManager.swift`) for the query/purchase/acknowledge/restore operations and `AppHelper.isUserPremium` (`AppHelper.swift:39-45`) for the entitlement derivation. Adds `SubscriptionError` — a new sealed interface + `RuntimeException` pair modeled on the existing `AuthError`/`AuthException` pattern (`core/network/.../auth/AuthResult.kt:19-34` + `AuthRepository.kt:203-206`) — because no general `AppError` type exists in the codebase (verified: 0 hits for `AppError`).

- Add `SubscriptionProduct` + `SubscriptionPlan` (`@Serializable`, Compose-free) to `core/model/` — the projection of a Play `ProductDetails` into the iOS `SubscriptionScreen` card shape: `planId`, `title`, `priceLabel` (Play's localized `formattedPrice`), `periodLabel`, `pricePerMonthEquivalent` (the grey secondary line on the yearly card, iOS `SubscriptionViewModel.mothlyPriceForYearlySubscription()` `:81-91`), `hasFreeTrialOffer: Boolean`, `offerTag: String?`, and a `isYearly: Boolean` discriminator mirroring iOS `InAppProduct { monthly, yearly }` (`InAppManager.swift:16-19`). Product IDs mirror iOS 1:1: `video_call_monthly` and `video_call_yearly_sub`.

- Add `SubscriptionProductType` enum with exactly two values — `MONTHLY("video_call_monthly")` and `YEARLY("video_call_yearly_sub")` — mirroring iOS `InAppProduct`, with `rawValue` written verbatim to `Users.subscriptionType` so a user who subscribed on iOS reads as premium on Android and vice versa.

- Add `SubscriptionScreen` + `SubscriptionContent` (11.2) in `feature/subscription/plans/` — mirrors iOS `SubscriptionScreen.swift` (195 lines) exactly: `#68B6CC` full-bleed background, `.ignoresSafeArea(edges = .top)`, 320-pt top image band, "Welcome {nickname}" (lato 24 medium, nickname fallback `"Klouder"`), the feature blurb string, the conditional "Start with a 1 week free trial." line, exactly **two** plan cards (Monthly, Yearly) as white rounded-24 rectangles with a 2-pt black stroke on the selected one, the selected-price caption "1 week free, then {price}", a black-capsule full-width subscribe button labelled "Try It Free" when a trial offer is present and "Subscribe" otherwise, a "Restore Purchase" text button, and the privacy-policy / term-of-use link row. Selection is single-select, defaulting to `MONTHLY`. The gray per-month-equivalent line renders only on the yearly card. No "save X %" badge, no "what's included" list — neither exists in iOS.

- Add `SubscriptionSuccessScreen` + `SubscriptionSuccessContent` (11.3) in `feature/subscription/success/` — mirrors iOS `SubscriptionSuccessScreen.swift` (43 lines): 120×120 checkmark-seal glyph, "Subscription activated successfully" (lato 26 bold), a white-capsule full-width "Done" button, `#68B6CC` background, no back affordance.

- Add `SubscriptionViewModel` (`@HiltViewModel`) — the UDF contract for 11.1/11.2. Exposes `SubscriptionState(products: AsyncValue<List<SubscriptionProduct>>, selected: SubscriptionProductType, isTrialEligible: Boolean, isPurchasing: Boolean, isRestoring: Boolean, error: SubscriptionError?)` and `Channel<SubscriptionNavEvent>` with events `PurchaseSucceeded(plan: SubscriptionProductType)`, `PurchaseFailed(error: SubscriptionError)`, `Restored(plan: SubscriptionProductType)`, `OpenPrivacyPolicy`, `OpenTermsOfUse`, `Dismissed`. On `PurchaseSucceeded` the VM runs the full iOS write sequence: acknowledge the purchase → derive `expiryDate` from the purchase token → `SubscriptionRepository.grantEntitlement(...)` writes `Users/{email}` → refresh the session cache.

- Add `SubscriptionSuccessViewModel` (`@HiltViewModel`) for 11.3 — trivial; owns the single `Dismissed` event. Added for contract consistency with every other screen in the codebase (every screen in P0–P7 has a `@HiltViewModel`).

- Add `SubscriptionFirestoreApi` (`@Singleton`) in `feature/subscription/data/network/` with `setSubscription(email, expiryDate, planId, platform)` — a Firestore `updateData` writing exactly the three iOS fields (`subscriptionExpiryDate`, `subscriptionType`, `subscriptionPlatform`), and `clearSubscription(email)` using `FieldValue.delete()` on the same three, mirroring iOS `UserRepository.setUserFree()` (`:149-163`) even though iOS has no live caller for it. Resolves the document by **email**, matching the repo-wide `Users/{email}` document-key convention (`UserFirestoreApi.kt:12-27`) — **not** `codeUser`, and **not** the lowercase `users/{uid}` path used by the FCM-token writes. Mirrors iOS's no-op-on-identical-expiry guard (`UserRepository.swift:168`: `guard user.subscriptionExpiryDate?.dateValue() != expiryDate`).

- Add `SubscriptionCloudFunctionsApi` (`@Singleton`) in `feature/subscription/data/network/`, modeled line-for-line on P6's `feature/profile/.../data/network/CloudFunctionsApi.kt` — exposes `verifyPurchase(token: String, productId: String): Result<SubscriptionVerificationResult>` against the `verifySubscription` HTTPS-callable, plus `SubscriptionVerificationResult` (a `@Serializable` DTO carrying the authoritative `expiryDate`, `isActive`, and `autoRenewing` computed server-side via the Google Play Developer API). `FirebaseFunctions` is already provided as a singleton by `core/network/.../di/FirebaseModule.kt:39-41`, so no new Hilt provider is required. The Cloud Function itself, its Play Console service-account credentials, and the RTDN Pub/Sub → function subscription are **external to this repository** (see audit finding 4) and are specified as a contract, not authored here.

- Add `PremiumGate` (`@Singleton`) in `feature/shell/` — mirrors iOS `AppTabController.showSubscriptionScreen()` (`SwiftUI/TabView/AppTabController.swift:209-229`) and `LoginVC.showSubscriptionScreen()` (`UserLoginVC`/`LoginVC.swift:219-232`). Both iOS gates carry an identical four-clause guard: already-open, logged-in, `isSubscriptionActive == false`, `isUserPremium == false`. Android reproduces all four clauses and adds a fifth (`wasDismissedInThisSession`) that iOS gets implicitly from `isSubscriptionOpened()` inspecting `presentedViewController`. Exposes `shouldPresent: StateFlow<Boolean>` and `requestPresent()` / `markDismissed()` / `markSatisfied()`.

- Add `SubscriptionRoute` sealed class in `feature/subscription/navigation/` with `Plans` and `Success` cases; register both as full-screen top-level routes on the root `NavHost` in `AppShell` (bottom-bar-hidden via the existing regex at `AppShell.kt:111-113`), and wire the gate's `requestPresent()` to navigate to `SubscriptionRoute.Plans`.

- Add a "Premium" `ProfileMenuRow` to `feature/profile`'s menu (between "My Data" and the conditional "My Communities" row), always visible, plus `ProfileNavEvent.OpenPremium` and `ProfileViewModel.onPremiumTap()`. The row's trailing edge renders the current plan label ("Premium" / "Monthly" / "Yearly" / "Active until {date}") — which requires adding an optional `trailingText: String?` slot to `ProfileMenuRow`, the first shared-component change P0–P7 has needed. **Android-only surface**: see audit finding 1.

- Add `User.isUserPremiumNow: Boolean` and `User.subscriptionExpiryInstant: Instant?` derived properties to `core/model` — the Android port of iOS `AppHelper.isUserPremium` (`AppHelper.swift:39-45`), since the raw `isPremium` field on the Android model is only ever a server-written hint and iOS **ignores it** in favour of the expiry comparison. `subscriptionExpiryDate` is already a `String?` on the Android model and is parsed as ISO-8601 via `kotlinx-datetime`, matching the repo's P1–P7 serialization convention.

- Add `SessionRepository.updateUser(transform: (User) -> User): Result<Unit>` to `core/storage` — the only new write path. Needed because `setSession(token, expiresAt, user)` is the sole existing writer and requires a live token the billing flow does not have. Preserves the token and `expiresAt` verbatim and replaces only the `user` field, keeping the write atomic.

- Close the `UserFirestoreApi.toUserOrNull()` read-path gap: map `isUserPremium`, `subscriptionExpiryDate`, `subscriptionType`, and `subscriptionPlatform` when decoding a `Users/{email}` document. Today only `FirestoreAuthApi.fetchUser` (`:190`) maps `isUserPremium`; every profile read drops the subscription fields on the floor.

- Pass the per-phase exit checklist (`./gradlew :app:assembleDevDebug`, install on API 26 + API 35 emulators, no crashes, lint, unit tests, screenshots, demo walkthrough, `phase-8-end` git tag).

## Capabilities

### New Capabilities

- `play-billing`: The Google Play Billing integration layer. `BillingClientApi` as the single `BillingClient` wrapper (connection state as a `StateFlow`, `QueryProductDetails`, `QueryPurchases`, `launchBillingFlow`, `acknowledgePurchase`, `queryPurchasesAsync(SUBS)` for restore, `endConnection`); the two-product catalog `video_call_monthly` / `video_call_yearly_sub` mirroring iOS `InAppProduct`; the `SubscriptionError` taxonomy (`BillingUnavailable`, `ProductUnavailable`, `UserCancelled`, `NetworkError`, `PurchasePending`, `NotAcknowledged`, `Unknown`); the `BillingClientStateListener` → `ConnectionState` mapping so the VM never touches `BillingClient` directly; and the rule that every purchase is acknowledged before any entitlement is granted. Includes the dev-flavor caveat: the `com.kornerz.kornerz.dev` application id is not a registered Play listing, so billing is unavailable on the dev flavor unless a separate Play app is created — the connection state is `Disconnected` and the plans screen renders a non-fatal notice rather than crashing.

- `subscription-plans`: Screens 11.1, 11.2, and 11.3. `SubscriptionScreen`/`SubscriptionContent` (11.1 host + 11.2 view) reproduces iOS `SubscriptionScreen.swift` structure — `#68B6CC` background, 320-pt top image band, "Welcome {nickname}" with the `"Klouder"` fallback, the feature blurb, the conditional free-trial line, exactly two white rounded-24 plan cards with a 2-pt black selected stroke, the selected-price caption, a black-capsule "Try It Free"/"Subscribe" button, "Restore Purchase", and the privacy-policy / term-of-use row. `SubscriptionSuccessScreen`/`SubscriptionSuccessContent` (11.3) reproduces the checkmark-seal + "Subscription activated successfully" + white-capsule "Done" screen. Single-select plan state defaults to `MONTHLY`; the grey per-month-equivalent line renders only on the yearly card; no discount badge and no "what's included" list (neither exists in iOS). Render states: loading (products not yet resolved), error + retry, and loaded.

- `premium-entitlement`: The premium state on `User` and its persistence. `User.subscriptionExpiryDate` (ISO-8601 `String?`), `subscriptionType` (`SubscriptionProductType.rawValue`), `subscriptionPlatform` (`"Android"` on purchase, mirroring iOS's `"iOS"`), and `isUserPremium`; the derived `User.isUserPremiumNow` / `User.subscriptionExpiryInstant` projections that mirror iOS `AppHelper.isUserPremium` (`expiryDate > Date()`) and ignore the raw `isUserPremium` bit; `SubscriptionFirestoreApi.setSubscription` writing exactly the three iOS fields via `updateData` with the identical-expiry no-op guard; `clearSubscription` deleting them via `FieldValue.delete()`; `SubscriptionRepository.grantEntitlement` / `revokeEntitlement`; and the `Users/{email}` document-key resolution contract.

- `premium-gate`: The paywall gate. Reproduces the four-clause iOS guard from `AppTabController.showSubscriptionScreen()` — already-open, logged-in, no active Play entitlement, `isUserPremium == false` — plus a per-process dismissal latch so the paywall is presented at most once per app session. Fires from exactly two places, both mirroring iOS: immediately after a successful login (`LoginVC.showSubscriptionScreen()`) and on shell resume / entitlement re-emit (`AppTabController`'s `CombineLatest` sink). Navigates to `SubscriptionRoute.Plans` when every clause passes; `markSatisfied()` when a purchase completes or an active entitlement is detected so the gate never re-fires mid-session. Explicitly does **not** fire from deep links or notifications (iOS has no such path).

- `subscription-verification`: Server-side purchase verification and the RTDN reconciliation contract. `SubscriptionCloudFunctionsApi.verifyPurchase(token, productId)` against the `verifySubscription` HTTPS-callable, returning the authoritative `SubscriptionVerificationResult(expiryDate, isActive, autoRenewing)` computed server-side via the Google Play Developer API; the client-side rule that a locally-verified purchase grants entitlement **optimistically** (matching iOS's on-device `checkVerified`) while the server result is authoritative on the next app launch; the reconciliation path for the `docs/project-brief.md:264` risk ("RTDN can be delayed; need graceful fall-back for users who purchase but the server doesn't see it for minutes"); and the explicit statement that the Cloud Function, its service-account credentials, and the Pub/Sub RTDN subscription live outside this repository, with the Android side holding only the callable client and the DTO contract.

### Modified Capabilities

- `user-profile`: The Profile menu SHALL add a **"Premium"** row, always visible, positioned between the "My Data" row and the conditional "My Communities" row. Tapping it emits a new `ProfileNavEvent.OpenPremium` and routes to `SubscriptionRoute.Plans`. The row's trailing edge SHALL render the current premium state (`Premium` when free, `Monthly`/`Yearly` when subscribed, `Active until {date}` when a future expiry is present). **This row has no iOS parity target** — `UserProfileVC.setupMenuList()` inserts no premium row and `TypeOfUserInfoCell` has no premium case; the Android row is the manual entry point supplementing the two automatic iOS gates. Requirement change to the Profile screen's menu composition and its `ProfileNavEvent` set.

- `user-profile-domain`: The `User` model's subscription fields stop being write-only decoration. Four fields — `isUserPremium` (`@SerialName("isUserPremium")`), `subscriptionExpiryDate`, `subscriptionType`, `subscriptionPlatform` — become live: `SubscriptionFirestoreApi` writes three of them, `UserFirestoreApi.toUserOrNull()` must map all four on read (today it maps none), and two derived projections (`isUserPremiumNow`, `subscriptionExpiryInstant`) are added. The existing `User` KDoc claim that these fields are "populated by the billing flow introduced in P8" becomes true rather than aspirational. Also corrects the stale `Users/{userCode}` claim in the existing `user-profile-domain` spec text — the document key is the **email**.

- `session-storage`: The `SessionRepository` write API gains `suspend fun updateUser(transform: (User) -> User): Result<Unit>`, which preserves the stored `token` and `expiresAt` verbatim and atomically replaces only the `user` field. Required so the cached premium state refreshes after a purchase or a server-verification round trip, given `setSession` is the only existing writer and requires a live token.

- `android-app-shell`: The root `NavHost` SHALL register `SubscriptionRoute.Plans` (`subscription/plans`) and `SubscriptionRoute.Success` (`subscription/success`) as top-level full-screen routes that hide the bottom bar (adding `subscription/.*` to the bottom-bar-hidden regex at `AppShell.kt:111-113`). `ShellViewModel` SHALL own the `PremiumGate` collection: it navigates to `SubscriptionRoute.Plans` when the gate opens, and `SubscriptionRoute.Success`'s "Done" event pops back and marks the gate satisfied.

- `android-build`: One new third-party dependency — `com.android.billingclient:billing-ktx` — added as catalog alias `android-billing` in `gradle/libs.versions.toml` (v7.x, satisfying the `docs/phases.md:259` "v6+" floor), consumed via `implementation(libs.android.billing)` by `feature/subscription` and by `app` (for the manifest-merge-driven `com.android.vending.BILLING` permission and the Play license check). No per-module `repositories {}` block is added because `settings.gradle.kts` declares `RepositoriesMode.FAIL_ON_PROJECT_REPOS`. All other libraries (Compose BOM, Hilt, Navigation-Compose, Coil, Firebase Auth/Firestore/Storage/Cloud Messaging/Functions KTX, kotlinx-datetime, kotlinx-serialization) are already pinned and reused.
